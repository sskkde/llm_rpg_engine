# [历史目标，已被替代] V2：基于 DSH 插件包的 RPG 引擎

> **历史状态**：本文保留原始正文，记录曾讨论的 DSH 原生迁移目标；该目标已被用户确认的新 RFC 中 Python（FastAPI + Next.js）演进方向取代。本文不再是当前目标、唯一权威或实施依据。当前设计基线与四阶段路线见 [RFC（LLM RPG Engine 设计总结）](design/llm_rpg_engine_design_summary_2026-10-08.md) 与[路线图草案](design/roadmap-draft.md)。本文未改写的下文仅供历史参考，不代表当前计划或已交付能力。

## 1. 产品目标与范围

V2 将 LLM RPG Engine 演进为基于 DeepSeek Harness（DSH）插件包交付的单人叙事 RPG：最终形态为 host+client hybrid 插件，提供原生 Node.js/TypeScript 领域内核与 React 客户端。玩家可完成有完整主线与结局复盘的单人游戏；支持自由输入与推荐行动、任务/背包/关系/地点和轻战斗闭环、NPC 记忆、世界时间、存档及内容管理。沿用现实现支持的中文与英文体验，具体兼容性须在实施和验收中确认。

**明确不在本次 V2 范围**：多人、支付、UGC 平台、原生 App、开放世界、复杂养成。不得把未验证能力、PoC 或计划表述为已实现。

## 2. 目标运行形态与迁移

- 最终交付为 DSH host+client hybrid 插件包：host 侧承载原生 Node/TypeScript RPG 领域内核和 DSH 集成，client 侧为 React UI。
- FastAPI 与 Next.js 不属于最终运行依赖。Python 桥接只允许作为迁移过渡路径；需定义版本化的对外协议，明确身份、幂等、取消和恢复语义，并通过兼容性与故障验收后再推进原生迁移。
- V1 现有服务和数据不可被默认视为已迁移。迁移前需盘点数据/内容、定义导入与回滚边界；具体实施方案及兼容策略属于后续决策。
- 不在本文预设未经验证的 DSH 版本、数据库或最终存储产品。所有外部 API/能力以实施时验证的公开接口和证据为准。

## 3. 责任边界

### DSH 宿主负责

模型适配与调用、插件生命周期、工具 guard、slots UI 承载及宿主集成。不得假设 DSH 会自动提供 RPG 权限隔离、账户 ACL 或跨记录原子事务。

### RPG 插件负责

权威游戏状态存储与事务边界、玩家可见性投影、按 campaign 与 NPC 身份隔离的记忆检索及带来源的记忆写入、规则/任务/剧情/世界时间、存档、幂等、恢复与回放。DSH sessionId 是宿主会话标识，不得与 campaign、save 或 NPC 身份混用；读档或状态分支后必须丢弃过期模型上下文并从权威状态重建。

### 模型调用与上下文

默认采用显式 messages 的独立 one-shot 模型调用，按回合构造最小必要上下文。常驻 NPC Agent 可选，仅为自主行为或缓存机制，不是游戏记忆权威。不得 fork 主会话、依赖宿主全局私有记忆或把共享历史当作权限隔离。memory-first 默认关闭是 V1 基线，不是冻结的 V2 开关默认值；V2 必须逐条定义读取/写入策略。

## 4. 存储、权限与安全约束

- storage-domain 已知能力只有单记录 durability/update；在证明多记录事务前不得把它当作 RPG 多实体原子提交方案。后端存储选型须在实施前决策，并通过断电/进程中断、并发冲突、重试幂等、部分失败、恢复及回放验收；不得一刀切假定 JSON 或 KV 足够。
- 玩家模式不得暴露宿主 shell/file 工具、NPC 秘密、模型 reasoning 或调试信息。所有自定义路由需验证身份、会话/存档归属及适用的 CSRF 防护（如采用 cookie）。本地可信单用户宿主不宣称支持公网多租户。
- 审计 LLM middleware、插件及日志边界，验证请求、提示词、秘密、输出和调试数据不会越权暴露；明确日志保留与敏感信息处理策略。
- 旁白必须先缓冲生成结果，再完整校验、持久化，最后展示正文。进度事件可实时传输，但未校验正文不得直接外发。此设计降低风险，不承诺绝对零泄漏；失败/取消路径必须验证不会重复展示或留下错误状态。

## 5. 迁移风险与负例验收

以下均是**待验证的旧代码风险线索**，不是已修复声明，也不是对 V1 行为的最终定论。迁移验收应将其作为必须排除的负例，并以运行证据确认：

- [`backend/llm_rpg/core/turn_service.py:1477-1483`](../backend/llm_rpg/core/turn_service.py#L1477-L1483) NPC fallback 可能从全局日志取得事件文本，未证明经过 NPC 感知投影。
- [`backend/llm_rpg/core/turn_service.py:1942`](../backend/llm_rpg/core/turn_service.py#L1942)、[`3272`](../backend/llm_rpg/core/turn_service.py#L3272)、[`3402`](../backend/llm_rpg/core/turn_service.py#L3402) 的旁白发送与外层校验顺序存在早发、重复发送风险线索，须验证拒绝时未校验正文零外发且无重复。
- 先提交模板日志、再多次写状态/事件/记忆的路径不能视作整个回合单一原子事务；须验证崩溃恢复与一致性。
- [`PlotBeatResolver`](../backend/llm_rpg/core/plot_beat_resolver.py) 存在不等于正式接通主回合链路；须用行为测试证明。memory-first 默认 off 是 V1 基线，不是冻结的 V2 开关默认值。

## 6. V2 里程碑（全部 planned / not-started）

不得添加臆造日期、完成率或将计划标成完成。每个阶段须保留可复现证据，并在阶段门通过后才能推进：

1. **能力 PoC**：验证 DSH hybrid、公开模型调用、slots、生命周期和安全边界；证明 RPG 所需状态/记忆/旁白链路可行，记录限制与失败模式。
2. **内核边界与桥接**：定义领域状态、身份/协议、可见性投影、记忆来源、幂等/取消/恢复契约；若使用 Python 桥接，证明它仅为明确的过渡边界。
3. **原生迁移与 UI**：实现原生 Node/TypeScript 领域内核、React 客户端、存档与内容管理；迁移/回滚路径有验证证据，最终运行不依赖 FastAPI/Next。
4. **故障、权限与完整通关发布门**：完成安全和故障负例、事务/恢复/回放验收；通过从新档到主线结局及结局复盘的完整通关，中英文关键路径验证，并确认交付包与宿主集成。

## 7. 发布验收门

V2 发布前须提供可复验的实现与测试证据，至少包括：

- 完整单人主线、行动推荐与自由输入、任务/背包/关系/地点/轻战斗、NPC 记忆、世界时间、存档和结局复盘的端到端通关。
- campaign/save/NPC 隔离、可见性与记忆来源验证；读档后无旧上下文污染；玩家工具面无宿主 shell/file、秘密、reasoning 或调试泄漏。
- 旁白缓冲—校验—持久化—展示顺序；拒绝、取消、断连及故障场景不提前发送正文、不重复提交，且具备恢复证据。
- 已选存储后端的多记录一致性、幂等、故障恢复及回放证据；身份/归属/CSRF（适用时）及日志/middleware 审计结果。
- DSH 插件 host+client 的构建、安装/加载、生命周期和卸载验证；协议版本与迁移策略明确。最终运行依赖不含 FastAPI/Next，桥接不被误列为最终架构。
